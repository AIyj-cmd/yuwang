# CODEX_BACKEND_PROMPT.md

请你先阅读并严格遵守：

```txt
docs/CODEX_BACKEND_CONSTRAINTS.md
```

你只负责 yuwang 项目的后端优化，不要修改前端页面、样式、布局、导航和视觉组件。

## 本次任务目标

1. 检查后端接口是否稳定；
2. 检查用户提交数据是否有后端校验；
3. 检查数据库约束和兼容迁移是否合理；
4. 检查权限边界是否存在越权风险；
5. 检查错误处理是否清晰；
6. 检查列表接口是否有分页和数量限制；
7. 检查通知、搜索、分享卡、个人画像、小组周目标、管理后台、AI 裁判边界是否符合项目规则；
8. 在不破坏现有前端调用的前提下优化后端代码。

## 重点检查

1. Fish Power Score 是否始终由后端计算；
2. 客户端是否可能伪造分数、身份、管理员权限；
3. 搜索空关键词是否返回空结果；
4. 搜索结果是否只展示 approved 且 public 内容；
5. 分享卡 GET 是否只读，不增加 share_count；
6. 分享卡 POST 是否只在 generate、copy_text、share_link 动作下增加分享次数；
7. 通知是否统一入口写入；
8. 通知是否有 dedupe_key；
9. 小组周目标是否只在明确业务事件下同步检查；
10. 后台写操作是否写入 admin_audit_logs；
11. AI 裁判是否没有被擅自接成自动审核、自动封禁或自动处罚流程。

## 禁止修改

1. 前端视觉；
2. 前端页面；
3. 前端组件；
4. 前端路由结构；
5. 前端样式；
6. API 已有路径和字段，除非提供向后兼容方案；
7. SQLite 旧数据；
8. 管理后台前端布局。

## 验证命令

完成后至少运行：

```bash
npm run typecheck
npm run build
```

并检查：

```txt
GET /api/health
GET /api/options
GET /api/leaderboards
GET /api/auth/me
GET /api/admin/auth/me
GET /api/admin/dashboard/summary
```

## 输出要求

完成后请输出：

1. 修改了哪些后端文件；
2. 修改了哪些接口；
3. 是否修改数据库；
4. 是否新增或调整兼容迁移；
5. 新增了哪些校验；
6. 新增了哪些权限判断；
7. 是否影响前端；
8. 是否影响 SQLite 旧数据；
9. 通知、搜索、分享卡、个人画像、小组目标、管理后台、AI 裁判是否符合边界；
10. 如何测试；
11. 是否还有风险点。
