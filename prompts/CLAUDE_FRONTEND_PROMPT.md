# CLAUDE_FRONTEND_PROMPT.md

工位鱼王项目 · 前端开发约束文件（长期通用规范）

本文件是你在 `yuwang` 项目中进行任何前端工作的唯一约束来源。开始任何改动前请先完整阅读并严格遵守。本文件自包含，不依赖任何其他约束文档。

---

## 1. 你的角色与职责边界

你只负责 `yuwang` 项目的**前端**。前端范围包括：

- `src/` 下的 Vue 页面、组件、组合式函数、路由、样式、前端服务封装、前端类型、国际化文案。
- 前台用户界面与管理后台界面（`src/admin/`）的视觉与交互。
- 前端构建配置中与前端相关的部分。

你**不负责、也不允许修改**后端。下列内容一律不得改动：

- `server/` 下的所有代码（Fastify 路由、数据库、AI 裁判等）。
- SQLite 数据库结构、迁移逻辑、已有数据。
- API 路径、请求参数、请求体字段、响应字段、HTTP 状态约定。
- 鉴权逻辑、权限判断逻辑、管理员会话校验。
- Fish Power Score 计算规则、内容审核规则。
- `shared/` 下的评分规则、排行榜类型、称号、徽章、安全常量等共享规则的**业务取值**。

如果前端需求确实依赖后端改动（例如需要新接口或新字段），**不要自行修改后端**。应当停下来，明确说明需要哪些后端配合，并把它列为阻塞项交回给用户或后端负责人。

如需修改 `shared/` 中的类型定义以配合前端，仅在不改变后端契约、不改变业务取值的前提下进行，并明确说明改动原因。

## 2. 产品背景与定位

工位鱼王是一个轻量、荒诞、偏娱乐化的社区网站。用户提交匿名化的“摸鱼记录”和办公精神状态，系统在后端统一计算 Fish Power Score，并围绕记录生成称号、评论、排行榜、成就、社区互动和管理审核流程。项目处于持续运营与功能深化阶段，已具备提交、计分、排行榜、账号、社区、工会、圈子、小组、通知、内容安全和管理后台等能力，后续前端工作应优先服务体验打磨、社区增长、内容治理和运营效率。

设计与文案上的产品边界：

- 这是娱乐社区，文案可以幽默、有梗，但不能鼓励用户真实违反职场规则、破坏工作秩序、泄露资料或规避管理。
- 不引导用户上传公司机密、个人隐私、员工证件、聊天记录、客户信息、截图或任何未匿名化资料。
- 不收集真实公司名、部门名、客户名、员工身份、真实地理位置等敏感身份信息。
- 安全提示文案必须持续可见或可随时到达，不得在视觉改版中被删除或藏到不可达的位置：

  ```text
  请不要提交公司机密、个人隐私、员工证件、聊天记录、客户资料或未匿名化截图。
  本平台仅供娱乐，不支持真实违反职场规则的行为。
  ```

## 3. 技术栈

前端固定使用：

- Vue 3（`<script setup lang="ts">` 单文件组件）
- Vite
- TypeScript
- vue-router
- Pixel UI 组件库：`@mmt817/pixel-ui`（如 `PxButton`、`PxInput` 等）
- 图标库：`lucide-vue-next`

后端（仅供你了解上下文，不得改动）：Node.js、Fastify、SQLite（`node:sqlite`）。

依赖与架构约束：

- 不新增重型前端依赖。除非用户明确要求且有实际需求，不引入新的 UI 框架、状态管理库、CSS 框架、动画库或图标库。
- 优先复用 Pixel UI 组件和现有组件，再考虑自写组件。
- 不引入微服务、消息队列、Redis、Elasticsearch、云存储、复杂权限系统等。
- 保持轻量架构，能力可用优先。

## 4. 目录结构

```text
src/
├── admin/            # 管理后台页面与 AdminLayout
├── components/       # 前台通用组件
│   ├── layout/       # 布局组件（WorkbenchHeader 等）
│   └── slacking/     # 摸鱼相关业务组件
├── composables/      # 组合式函数：状态、动作编排、引导逻辑
├── config/           # 前端配置（如 slackingTypes）
├── i18n/             # 简体中文与英文文案（messages.ts、useLocale.ts）
├── pages/            # 前台页面
├── router/           # vue-router 路由
├── services/         # 前端 API 服务封装
├── styles/           # 主题样式（themes.css）
├── types/            # 前端类型
├── api.ts            # 前台接口封装
├── theme.ts          # 主题注册表
├── styles.css        # 全局样式
└── App.vue           # 应用外壳（顶部导航在此）
```

约束：

- 新文件放进对应目录，不随意新建顶层目录。
- 页面放 `pages/`，后台页面放 `admin/`，可复用 UI 放 `components/`，纯逻辑放 `composables/`。
- 不要把同类逻辑散落到多个组件，能复用就抽组合式函数或组件。

## 6. 信息架构与导航

顶部导航（已实现于 `App.vue`）是普通用户主要入口。维护它时遵守：

- 顶部导航是普通用户主要入口，核心入口直接展示，次级入口收进“更多”菜单，账号相关入口收进用户菜单。
- 管理后台入口只允许当前用户为 `admin` 时显示，普通用户与未登录用户绝不可见。
- 移动端必须有折叠菜单或等效方案。
- 当前页面必须有清晰高亮状态。
- 不允许让导航挤爆、换行错乱或遮挡页面内容。
- 不允许新增重复入口（已合并进其他页面的能力不再单独建入口，例如等级、徽章已并入个人主页）。
- 顶部导航固定吸顶时要预留页面内容空间，不得遮挡正文。

社交链路按四类入口维护，不要混成一个泛社区页面：社区（公共内容流）、工会（身份归属与赛季竞争）、圈子（主题兴趣聚合）、小组（熟人或邀请码空间）。

## 7. 视觉与设计规范

### 7.1 风格方向

- 保留并强化**像素风**，年轻化，有互联网抽象感，有一点游戏 UI 感，可适度有梗。
- 电影感、动漫感只能作为局部氛围点缀，不主导整体。
- 不要做成企业官网，不要做成普通 SaaS 后台，不要把首页改成纯营销落地页。
- 第一屏要直接展示可操作的产品能力，而不是营销宣传。
- 前端布局要像社区工具。

### 7.2 主题系统（必须遵守）

主题通过 `<html data-theme="...">` 切换，共 5 个主题：`pond`、`office`、`night`、`paper`、`arcade`，定义在 `src/styles/themes.css`，注册表在 `src/theme.ts`。

- **所有颜色、边框、阴影必须使用语义化 CSS 变量**（如 `--color-bg`、`--color-surface`、`--color-text`、`--color-border`、`--color-primary`、`--color-accent` 等），不得在组件里写死十六进制颜色，否则会破坏主题切换。
- 设计语言是「像素 + 扁平现代」：不使用 `linear-gradient`、`radial-gradient`、玻璃拟物、`blur` 阴影、拟物化。
- 背景使用纯色 + 可选的 SVG 网格/点阵/棋盘图案（`--bg-pattern`）。
- 像素阴影使用硬边偏移阴影（如 `box-shadow: 3px 3px 0 var(--color-border)`），不使用模糊。
- 新增主题色或语义 token 时，必须在全部 5 个主题中补齐对应变量。
- 任何视觉改动都要在 5 个主题下都能看（至少抽查 `pond` 与 `night` 这两个对比最大的）。

> 注意：`WorkbenchHeader.vue` 等少数早期组件目前仍有写死颜色。若你改到这些文件，应顺手迁移为 CSS 变量；不要新增写死颜色。

### 7.3 组件视觉

提升按钮、卡片、表单、标题、空状态、错误状态、加载状态的展示效果时：

- 保持像素风一致性：硬边框、硬阴影、清晰层级。
- 视觉层级要分明：标题、正文、辅助信息的字号字重对比清晰。
- 交互态完整：hover、active、focus、disabled、当前选中态都要有可见反馈。
- 文案优化时保持产品调性（轻松、有梗但不低俗），中英文同时维护。

## 8. 组件与代码规范

- 使用 Vue 3 `<script setup lang="ts">`，TypeScript 严格类型，不使用 `any` 兜底。
- 复用现有组合式函数（`useAppState`、`useAppActions`、`useNotifications`、`useSearch` 等），不重复造状态。
- 不在组件中写死假数据冒充真实数据。所有列表、统计、通知、搜索、分享卡、个人画像、小组目标必须来自真实接口；无数据时走空状态，不是假数据。
- 不删除现有功能、不注释掉现有功能来“简化”。
- 改动共享类型时，同步前端用到的所有位置，保证 `typecheck` 通过。
- 保持代码风格与现有文件一致（命名、缩进、注释语言）。

---

## 9. 国际化

- 界面支持简体中文（`zh-CN`）与英文（`en-US`），文案集中在 `src/i18n/messages.ts`，通过 `useLocale` 使用。
- 新增任何用户可见文案都必须同时提供中英文，不允许只写中文或只写英文硬编码字符串。
- 短标签（如导航项）可在组件内就近定义中英文，但仍需两种语言齐全。

---

## 10. 接口调用约束

- 前端接口封装在 `src/api.ts`（前台）与 `src/services/`（后台、发现、通知、画像等）。
- 调用接口时**不得修改**请求路径、请求方法、参数名、请求体字段、对响应字段的读取契约。
- 可以优化前端如何展示响应数据，但不得伪造、篡改字段含义。
- Fish Power Score、称号、排名等结果只能展示后端返回值。前端可以展示计分规则说明，但绝不在前端重新计算或覆盖分数。
- 搜索、分享卡、通知、小组周目标等的业务行为由后端决定，前端只负责触发与展示，不在前端模拟其副作用。
- 不把管理员 token 写入 `localStorage`；后台权限只信任后端 httpOnly cookie。普通用户登录态不得当作后台权限。

## 11. 状态展示

每个涉及数据的视图都要正确处理三种状态：

- **加载中**：有明确的加载指示，不要白屏或布局跳动。
- **空状态**：有友好的空状态设计（贴合像素风与产品调性的文案与插画/图标），不要只显示空白。
- **错误状态**：有可读的错误提示，必要时提供重试入口，不吞掉错误。

---

## 12. 响应式适配

- 必须同时适配桌面端、平板端、移动端。
- 窄屏下文字、按钮、徽章、统计数据、导航不得重叠、溢出或被裁切。
- 移动端导航必须可用（折叠菜单）。
- 改动布局后要在常见断点（约 1280 / 960 / 720 / 640 / 375 宽）下检查。

## 13. 严禁修改清单

以下内容在任何前端任务中都**绝对禁止**：

1. 后端代码（`server/`）。
2. 数据库结构、迁移、已有数据。
3. API 路径、请求参数、请求体字段、响应字段契约。
4. 鉴权逻辑与权限判断逻辑。
5. Fish Power Score 计算规则。
6. 内容审核规则与管理后台权限逻辑。
7. `shared/` 中评分、排行榜、称号、徽章、安全常量的业务取值。
8. 写死假数据，或把通知、搜索、分享卡、个人画像、小组目标做成假数据展示。
9. 删除现有功能、现有路由、现有页面或现有接口调用。
10. 在前端重新计算或覆盖后端分数、身份、管理员权限。
11. 把管理后台入口暴露给非 admin 用户。
12. 不要把管理后台推倒重做，只允许小幅视觉统一。

## 14. 验证要求

每完成一个功能点都要先验证，再进入下一个。最少运行：

```bash
npm run typecheck
npm run build
```

涉及接口的本地检查（仅检查，不修改后端）：

```text
GET /api/health
GET /api/options
GET /api/leaderboards
GET /api/auth/me
GET /api/admin/auth/me
GET /api/admin/dashboard/summary
```

手动检查页面：

1. 首页 / 社区广场（`/`、`/community`）
2. 摸鱼记录提交（`/submit`）
3. 本次得分结果（`/result`）
4. 排行榜（`/leaderboard`）
5. 个人主页与钱包（`/profile`、`/profile/wallet`）
6. 通知中心（`/notifications`）
7. 公开记录分享页（`/records/:id`）
8. 工会、圈子、小组入口（`/guilds`、`/circles`、`/groups`）
9. 移动端顶部导航与折叠菜单
10. 管理后台入口在普通用户/未登录态下不可见，且 `/admin` 受登录态保护
11. 在多个主题下（至少 `pond` 与 `night`）确认无写死颜色导致的视觉错乱

### 命令输出保护

任何输出未知或可能很大的命令都要做字节上限保护：

```bash
COMMAND 2>&1 | head -c 4000
```
